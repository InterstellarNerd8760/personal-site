03 / Field notes

The work between milestones.

Projects rarely move in a straight line. This is where the decisions, failures, fixes, and lessons belong.

01 / PRODUCTAccuracy is a feature, not a polish pass.+

For a learning product, a beautiful interface cannot compensate for a wrong answer. The useful work is often unglamorous: checking source material, improving question review, and making it easier to understand what to study next.

CENTAURI ACADEMY · PRODUCT PRINCIPLE

02 / HARDWAREA sensor reading is only useful if you can trust it.+

WALL-E depends on a chain of small systems: sensor communication, timestamps, storage, power, and recovery when something fails. The next useful milestone is not another feature. It is a repeatable test that proves the current path works.

WALL-E · ENGINEERING NOTE

03 / METHODBuild the smallest thing that proves the assumption.+

When a project feels complicated, isolate the uncertain part. Test that one thing, record what happened, then decide what to build next. It is faster than treating a big plan as proof that the pieces will work together.

04 / The horizon

Build useful things here.
Help build a future out there.

I want to work on the systems that make space more accessible: vehicles, orbital infrastructure, servicing, logistics, and the unglamorous engineering that makes ambitious missions possible.

That is a direction, not a claim about what I have already achieved. Right now, I'm learning by shipping software, working with hardware, studying the fundamentals, and getting closer to real engineering problems.
