# Modelling curated knowledge capacity

Run `python tools/knowledge_budget.py --copies 2` from the repository root for a deterministic byte ledger and 100, 300, 1,000, 3,000 and 5,000-article scenarios. The site renders these same build-time values. Decimal MB means 1,000,000 bytes.

The source ledger measures original bytes beneath `archive/`. The encyclopedia's text subtotal counts UTF-8 bytes of titles, paragraphs and limitations. Its metadata remainder includes JSON syntax, identifiers, hierarchy, editorial metadata, source references, review evidence and whitespace. The diagram category includes the vocabulary SVG. The current ZIP has a separate manifest and ZIP entry overhead. Browser indices are derived presentation assets.

The scenarios retain every non-encyclopedia archive source file as a fixed cost, including all 104 source JPEGs. The program removes the monolithic encyclopedia JSON and samples the observed distribution of compact article record sizes at evenly spaced quantiles. It adds a compact category dictionary, a binary ten-byte-per-record CAX1 index, 48 CAX1 framing bytes per record and per-record CAEC v1 block rounding. A full CAEC codeword consumes 255 bytes per 134 bytes of framed input. The value for one protected copy is multiplied by the requested physical copy count. The projection includes neither physical synchronization/slot-map overhead nor the mass of the carrier, and it budgets byte lengths rather than producing CAX1 records for arbitrary source file types.

These are projections at current draft lengths. More substantive articles, relevant diagrams, large reference lists and multiple languages may raise the average. The curated collection could share term definitions and diagram references, use binary relationship tables, and keep attribution in recoverable records rather than repeated inline. These choices need separately specified representations and tests. Compression begins only after a reader has the uncompressed bootstrap, test vectors and a taught decompressor. No compression credit is assumed here.

The 300-topic planning backlog has ten strands across the existing nine category IDs, with astronomy and physics split for planning. The first ten topics in each strand form the 100-topic Essential shortlist. Stable planning IDs do not assign article IDs or assert that an existing draft covers a topic. Record an editorial purpose, prerequisites and related records before assigning a new article ID. Existing article IDs remain resolvable as the site switches to individual record retrieval.
