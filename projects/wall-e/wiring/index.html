Wiring & diagnostics.

Current status: the wiring is not working reliably at all. It's a real pain in the ass. This is the latest attempted BME280 wiring, not a verified working circuit or a flight-qualified schematic.

01 / Latest attempted bench connection · Not working reliably

Pico → BME280.

This layout occasionally allowed the sensor to appear at address 0x76 and return chip ID 0x60, but repeated communication still fails with [Errno 5] EIO. Those brief successes do not establish stable wiring. The circuit is still being debugged, and no dependable measurement stream has been demonstrated.

Latest wire colors: white = VCC, gold = ground, black = SDA (gray in the diagram for contrast), purple = SCL. *Any correctly identified Pico GND works; physical pin 23 is one example.

03 / Diagnostic

Scan first. Then read.

from machine import I2C, Pin
i2c = I2C(0, sda=Pin(16), scl=Pin(17), freq=100_000)
print("I2C:", [hex(a) for a in i2c.scan()])
print("Chip ID:", hex(i2c.readfrom_mem(0x76, 0xD0, 1)[0]))
# Expected when responding: 0x76 and 0x60
  1. Disconnect power and check the labels on all four Pico and sensor connections.
  2. Replace or firmly secure questionable breadboard jumpers; don't rely on holding wires by hand.
  3. Reconnect, scan, read chip ID, and repeat measurements long enough to reveal intermittent failures.
  4. If read errors continue, isolate the sensor and connections before changing the software.
  5. Keep the formerly overheating SD module disconnected until its power and wiring have been inspected.

A scan result alone does not prove the sensor is reliable. The next milestone is repeatable measurements on secure wiring.
