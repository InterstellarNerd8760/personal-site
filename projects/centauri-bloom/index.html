Centauri Bloom.

Founding phase · Recruiting contributors

One model. Many contributors. Built from scratch.

Want something cool on your résumé? Help build Centauri Bloom from scratch. We're exploring how volunteers can build and train a small language model together, openly, using the computing resources they already have.

Find your first contribution →Download project brief

Why Bloom?

The name of our first model was inspired by the Anti-Doomer community. Bloom is an independent project, not an official initiative of that community. The goal is to turn optimism about technology into a practical, reproducible experiment in collaborative AI research.

This is not affiliated with BigScience's existing BLOOM language model. There is no trained model, live training network, or confirmed compute budget yet.

How it would work

  1. Start from a shared checkpoint. Use one architecture, tokenizer, training configuration and versioned dataset.
  2. Train independently. Workers download an assigned shard and complete a defined number of local steps.
  3. Submit an update. Record the parent checkpoint, data shard, step count, metrics and checksums.
  4. Validate and aggregate. Reject incompatible or suspicious updates; combine eligible updates from the same round, then evaluate before publishing the next checkpoint.

Initially the coordinator can be a maintainer-operated Python script. GitHub will host source code and Hugging Face is the proposed host for datasets and weights. We will study DiLoCo before selecting a distributed optimization method; ordinary checkpoint averaging is only a baseline experiment.

Proposed baseline: a small decoder-only PyTorch transformer trained from random initialization, with a shared tokenizer and a curated, appropriately licensed text dataset. Exact dimensions and hyperparameters will be recorded before the first run.

Where you can help

Training & ML

Implement a minimal transformer, run experiments, or compare aggregation algorithms.

Infrastructure

Build the worker workflow, artifact storage and reproducible validation.

Data

Document provenance, licenses and privacy boundaries for datasets.

Evaluation

Track held-out loss, test regressions and define responsible-use checks.

No experience is required to start learning. Expensive hardware is not required for documentation, data review or small tests. Participation is voluntary; use only hardware and services you're authorized to use.

Launch roadmap

  1. Agree on licensing, code of conduct, governance and initial model configuration.
  2. Publish the training scaffold and deterministic CPU smoke test.
  3. Train a baseline and two-worker round, then record and publish the result.
  4. Document failure modes, rollback and later distributed optimization experiments.

Join the founding effort

The independent repository and model hosting are not established yet. For now, propose a task or technical idea in the public website issue tracker, with “Centauri Bloom” in its title. No purchase or paid service is required to participate.
