Centauri Bloom.

Founding phase · Recruiting contributors

One model. Many contributors. Built from scratch.

Want something cool on your résumé? Help build Centauri Bloom from scratch. We're exploring how volunteers can build and train a small language model together, openly, using the computing resources they already have.

GitHub ↗Join Discord ↗How it works

Why Bloom?

The name of our first model was inspired by the Anti-Doomer community. Bloom is an independent project, not an official initiative of that community. The goal is to turn optimism about technology into a practical, reproducible experiment in collaborative AI research.

This is not affiliated with BigScience's existing BLOOM language model. There is no trained model, live training network, or confirmed compute budget yet.

How the project works

One shared project, three main platforms. Discord is for conversation; GitHub is the source of truth for code, tasks and technical decisions; Hugging Face is the planned home for versioned datasets and model weights.

  1. Develop. Discuss ideas in Discord, choose a GitHub issue, fork the repository and submit a pull request for review and testing.
  2. Experiment. Run independent training tests. Record the architecture, tokenizer, dataset version, training settings, hardware, metrics and checkpoint format. Independent experiments are not yet official model releases.
  3. Train together. Once a common architecture and tokenizer are agreed, workers will train on assigned shards from the same checkpoint. Compatible updates will be validated, aggregated and evaluated before promoting a new checkpoint. This network is still being developed.
  4. Release. Publish reviewed weights, configuration, tokenizer and model card on Hugging Face. A public chat interface and local inference are future goals.

Pretraining uses a licensed text corpus; instruction tuning uses reviewed prompt-response examples. See the technical architecture and development roadmap for the implementation details.

Community tools

A contributor is developing an independent Bloom website and browser-based training experiment. These are early community prototypes, not the official shared training network. Their compatibility with the central model and checkpoint format has not yet been established.

Proposed baseline: a small decoder-only PyTorch transformer trained from random initialization, with a shared tokenizer and a curated, appropriately licensed text dataset. Exact dimensions and hyperparameters will be recorded before the first run.

Where you can help

Training & ML

Implement a minimal transformer, run experiments, or compare aggregation algorithms.

Infrastructure

Build the worker workflow, artifact storage and reproducible validation.

Data

Document provenance, licenses and privacy boundaries for datasets.

Evaluation

Track held-out loss, test regressions and define responsible-use checks.

No experience is required to start learning. Expensive hardware is not required for documentation, data review or small tests. Participation is voluntary; use only hardware and services you're authorized to use.

Get involved

The initial code scaffold and local two-worker CPU smoke test are in the public repository. Start with the open issues and contribution guide. Keep project discussions in moderated channels and personal information and credentials private.
